# R13 · «Выбрано для семьи» vs подтверждённая доставка · 1.5.196

## Что исправляет кандидат

У локальной библиотеки есть `familyPublished`: это **выбранные для семьи сохранённые снимки**, а не подтверждённые копии на втором устройстве. Начиная с версии 1.5.196, локальный бейдж показывает «Выбрана для семьи» и счётчик показывает «Выбрано для семьи». Независимо от этого доставка должна иметь фактическое подтверждение семейного транспорта и чтение из изолированного профиля B.

Ветка основана на `lazy-world-scenes-195-after-r14` (PR #161); изменения не затрагивают контент детских книг, сохранения, рисунки, ключи и права доступа.

## Автоматическая проверка без реальных данных

- `node tests/regression.cjs`: семейный label должен отличать локальный выбор от подтверждённой доставки.
- `BROWSER=chromium node tests/browser-smoke.cjs` и `BROWSER=webkit node tests/browser-smoke.cjs`: после создания синтетической семейной копии в карточке показано «Выбрана для семьи». Проверка экспорта/сохранения и работа прежнего транспорта не снимаются.
- `node tests/studio-visual.cjs`: сравнение на текущем SHA и родительском SHA, без замены скриншотов заглушками.
- Проверить оба бюджета: стартовые пять файлов ≤1 000 000 B; cold-home encoded ≤1 200 000 B. Проверки из предыдущих PR не переносятся автоматически.

## Двухпрофильная приёмка на реальных устройствах

1. В тестовом окружении взрослый настраивает разрешённый сервер/семейный архив, контроль доступа, изолированные профили A и B. Не помещать в репозиторий секреты и реальные сказки ребёнка. Пока `family-cloud-config.json` содержит `enabled:false`, семейная долговременная доставка заблокирована.
2. На устройстве A создать **тестовую** книгу из трёх глав, трёх разных рисунков, заголовка и темы. Проверить локальный статус «Сохранено» без публикации и отсутствие новой книги на устройстве B.
3. Явно выбрать «Опубликовать для семьи». Прочитать состояние «выбрано/ожидает доставки» и дождаться подтверждённой записи на сервере/актуальном транспорте. До получения квитанции устройство A не должно сообщать, что родственник прочитал или сохранил книгу.
4. Из нового изолированного профиля B по семейной ссылке открыть именно этот тестовый экземпляр, проверить три главы, порядок/байты рисунков, тему и заголовок; обновить страницу и проверить сохранение на B. Записать подтверждённую серверную ревизию/ACK и время наблюдения.
5. Изменить на A вторую главу и один рисунок, отправить новую редакцию. Проверить B на актуальную версию после синхронизации. Отключить интернет сначала на A, затем на B: не должно возникнуть ложного статуса доставки или потери локальной работы.
6. Отозвать семейный доступ и подтвердить отсутствие последующих обновлений у B. Уже сохранённые копии B могут оставаться; UI должен предупреждать об этом до отзыва.
7. Протестировать ошибку квоты хранения на A и B, закрытие вкладки и перезапуск Safari. Не допускать удаления работы или сообщения «Доставлено» без реального подтверждения.

## Доказательства и release gate

Для каждой проверки фиксировать: шаг, устройство/движок, SHA приложения, тестовые данные и hash рисунков, фактический результат, снимок экрана без личных данных, ID server receipt/ACK, итог PASS/FAIL/NOT TESTED. Отдельно зафиксировать физический iPad/Safari (HARDWARE PENDING до проверки).

**GO только при фактическом A→B, безопасном повторном открытии, и полном QA на exact SHA.** Иначе R13 = BLOCKED, R18 = HARDWARE PENDING, общий релиз = **NO-GO**. Ни PR #162, ни зелёные mock-тесты не доказывают доставку семье.
